APK20 Public API v1.0.0

The catalog behind apk20.com, as JSON

Every page on this site is rendered from a public HTTP API, and that API is open. App metadata, complete version history, per-variant APK forensics down to declared permissions and file hashes, and the download-token flow are all reachable with a plain GET. No key, no account, no sign-up.

Base URL
https://www.apk20.com/playstore

The /playstore context path is part of the base URL, so every path on this site is written in full as /playstore/api/database/.... Responses are application/json throughout, and CORS is open, so browser code can call it directly.

Three calls, start to finish

Limits and expectations
Authentication
No API key or account. Catalog reads are anonymous; version-watch confirmation, unsubscribe, and status links use unguessable capability tokens issued only for that subscription. Treat those links as credentials.
Rate limits
Reads are not metered. Search is 20 requests per 10 minutes, per IP for distinct queries and token minting is 10 requests per 10 minutes, per IP, both answering 429 when exceeded. Requests with a crawler user agent are refused on search with a 403.
Stability
This is the API the site itself runs on, so it changes when the site does. Fields get added, and shapes can change without a version bump. Read what you need and tolerate what you do not recognise.
Support
No SLA, no uptime guarantee, no support commitment. If something is broken or you are building something interesting, the contact form reaches a human.

Field coverage varies per record. The catalog stores what the collector managed to read from a given build, so a variant may carry a SHA-1 but no SHA-256, or no permission list at all. Absent means unrecorded, not zero.
